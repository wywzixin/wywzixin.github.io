11. 几处需要再精确一点的地方

一、位置编码：课件画的是正弦余弦，GPT-3 用的是学出来的

图上那张 PE 公式（sin、cos、10000^(2i/d_model)）来自 2017 年原始 Transformer 的固定正弦位置编码——它是一个确定性函数，没有参数。

但 GPT-2、GPT-3 用的是可学习的位置嵌入表，GPT 原论文写得很直接：

We used learned position embeddings instead of the sinusoidal version proposed in the original work.

这两件事不能同时成立。而它正好解释了 §10 里为什么会有 2048 × 12288 = 25,165,824 个位置参数——正弦编码是固定的，没有参数可算；只有学出来的嵌入表才有参数量。

所以看到那张公式图时，把它当成「原始 Transformer 的设计」来看，不要和 GPT-3 的尺寸混成一个具体实现。课程里其实也提醒了这一点。

二、权重共享这件事是有争议的

§10 里说「GPT-3 沿用 GPT-2 架构、输入 Embedding 和输出矩阵共享」，所以最后那 6.176 亿不重复计算。这个说法网上分两派：

  • GPT-2 确实是共享的，OpenAI 的 GPT-2 实现里输出 logits 直接用输入词嵌入矩阵 wte 的转置，这是可以查证的。
  • 但 GPT-3 的论文并没有写明这一点。做可解释性研究的一派（Neel Nanda 等）认为 GPT-3 恰恰没有共享权重，理由包括 GPT-3 和 GPT-J 在这类现象上表现一致。

如果没共享，总量就要多 6.176 亿，约 1752 亿。

两边都四舍五入到 175B，所以官方那个数不受影响。但要清楚：「1746.04 亿」这个精确值只在权重共享成立的前提下才对。

三、4× 是 GPT-3 的配置，不是通用规则

FFN 中间层 49152 = 4 × 12288，这个 4 倍关系在 GPT-2/GPT-3 这一代里是标准配置，但别把它当成所有大模型的规则——后来很多模型用的是其他比例（8/3 倍、或者用门控结构）。算参数量时以模型自己的配置为准。

12. 小结

一、整条链路可以压成一句话： Embedding 把文字变成数字；位置编码告诉模型顺序；Attention 负责 Token 之间交流；FFN 负责每个 Token 自己加工；96 层负责反复深化；Linear + Softmax 负责从词表里选出下一个 Token。

二、形状走一圈会回到原点。 输入 [3, 12288]，注意力中间拆成 96 个 [3, 128] 再拼回 [3, 12288]，FFN 中间扩到 [3, 49152] 再压回 [3, 12288]。每一层的输入输出形状相同，所以才能摞 96 层。

三、位置信息是相加，不是拼接。 加完形状不变，仍是 [3, 12288]。

四、因果 Mask 是自回归的关键。 它让训练时每个位置只能看自己和前面，从而可以一次并行地监督所有位置，同时又不泄露答案。

五、输出只取最后一个 Token 的向量。 训练时每个位置都在预测，但生成时只关心最后一行——它已经吸收了前面全部允许看到的信息。

六、50257 是词表大小，不是单词数。 一个 Token 可能是半个单词、一个汉字，或者标点。

七、1750 亿参数的算法：L × 12d² + Vd + n_ctx d。 96 层吃掉 99% 以上（约 1739.6 亿），其余是词嵌入 6.176 亿、位置嵌入 0.252 亿。参数几乎全在层里，而层里的参数又几乎全是 d² 那两个矩阵堆出来的。

八、三个要留意的点： 课件画的正弦位置编码属于原始 Transformer，GPT 系列用的是学出来的嵌入表；权重共享在 GPT-3 上是存疑的；FFN 的 4 倍不是通用规则。
