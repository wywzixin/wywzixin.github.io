6. yield：算一个、交一个，下次接着算

yield 是 Python 里用来创建**生成器（generator）**的关键字。

普通函数用 return 会立刻结束并返回结果。用了 yield 的函数会变成生成器函数，调用它不会立刻执行完，而是返回一个生成器对象。每次用 next() 或 for 循环去取下一个值时，函数才会从上次暂停的地方继续执行，直到再次遇到 yield。

所以 yield 和 return 的分工是：

  • return：一次把结果全算完，交出去，函数结束
  • yield：交出一个值，函数在这里暂停；下次再来要，从暂停的地方接着往下跑

把四次取值拆开看，就是函数在”跑 → 停 → 接着跑”之间来回：

平时一般不会手写 next()，直接 for 就行——for 会自动一次次取，取到 StopIteration 就结束，这个异常在循环里根本看不见：

为什么要用它：不把数据一次性装进内存

这是 yield 最实在的理由。读一个几百万行的日志：

换成返回列表，写法只差一点，内存差很多：

用 yield 的版本，处理到第 500 万行时，内存里只有那一行。这就是**”边走边给”和”先攒齐再给”**的区别。

判断标准：这份结果你是打算遍历一遍就扔，还是后面要反复用？ 遍历一遍就扔，用 yield；要反复用、要取长度、要按下标访问，那就返回列表。

两个要记住的点

  • 生成器只能遍历一次。 取完就空了，再 for 什么都不出来；要重新调一次函数，拿一个新的生成器。

with ... as ... 是 Python 的上下文管理器语法，主要用于：在进入代码块时自动获取资源，在离开代码块时自动释放资源。

9. 类型标注：list[str]、dict[str, Any]、type[X]

意思是：names 是一个列表，列表里的元素应该是字符串 str。

冒号后面是标注，等号后面才是值。标注不影响运行——Python 不会因为你标了 list[str] 就往里做检查，它只给 IDE 和 mypy 这类静态检查器看。

list[str] 这种小写泛型要 Python 3.9+（PEP 585）。老代码里写成 List[str]，那是从 typing import 的，现在没必要了。

type[X]：传的是类，不是实例

有一个标注容易读反：

type[X] 表示的是”X 的类对象本身“，也就是 X 这个类，或者它的子类。它不是表示”X 的实例”，而是表示”能创建 X 实例的那个类”。

11. Literal 比 Enum 轻在哪

要表达”这个字段只能取三个值之一”，传统写法是用 Enum：

缺点：

  • 必须额外定义一个类
  • 运行时是 Enum 对象，不是普通字符串
  • 序列化成 JSON 时比较麻烦（需要自己处理 .value，否则 json.dumps 抛 TypeError）
  • 代码稍微啰嗦一点

现在更推荐用 Literal：

优点：

优点 说明
更轻量 不需要单独定义一个类
运行时就是普通字符串 category 的值直接是 "read"，不是对象
序列化零成本 直接能转 JSON，不用额外处理
类型检查依然有效 静态检查器能拦住非法值
IDE 提示好 自动补全只会出现 "read" / "write" / "command"

代价也要说清楚：Literal 只给类型检查器看，运行时不做任何校验。 从 JSON 里读进来一个字符串，标了 Literal 也拦不住非法值——要运行时校验还得自己写判断，或者用 Enum / pydantic。它管的是”写代码时 IDE 会拦”，不管”跑起来时数据是脏的”。

12. 小结

真正要记住的只有三件事：

一、判断和推导都是”先说结果、后说条件”。 A if 条件 else B、[对每个元素做什么 for 元素 in 集合 if 条件]，条件和过滤都放在后面。

二、空容器是假值。 0、""、[]、{}、() 全都算假，所以 or 当默认值用会把它们一起兜掉。0 是有效值的时候，只能写显式判断。

三、类型标注不参与运行。 list[str]、type[X]、Literal 管的是写代码时的提示和补全，管不了运行时的数据。
